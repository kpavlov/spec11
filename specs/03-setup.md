# Setup: install and doctor

- **SETUP-01** MUST — `install` writes the skill to `<repo>/.agents/skills/spec11` and merges a spec11 entry into `.mcp.json`, keeping every other server and key.
- **SETUP-02** MUST — leave a `.mcp.json` that is not valid JSON untouched.
- **SETUP-03** MUST — `uninstall` removes only what `install` added, and deletes `.mcp.json` only if install created it.
- **SETUP-04** MUST — only read the global MCP config (`~/.claude.json`), never write it. (manual)
- **SETUP-05** MUST — `doctor` only reads: unless asked with `--fix`, it never runs `codegraph init` or `codegraph sync` and never writes files.
- **SETUP-06** SHOULD — `doctor` fails only when spec11 cannot run at all (no repo, an unreadable `spec11.json`); no specs is a warning with a hint (a sample requirement line and the folder names), and every other check still runs.
- **SETUP-07** MUST — build or refresh the CodeGraph index only when the user asks (`doctor --fix`, the Setup tab buttons, the dashboard's rescan button): `init` only when there is no index, `sync` only when there is one, and never automatically: not from a check, a startup, a push or a timed reload.
- **SETUP-08** SHOULD — `codegraph` takes `action=refresh`: run `sync` whenever an index exists and the binary is on PATH, also while a codegraph process runs (a running MCP server can have its file watcher off, `serve --mcp --no-watch`, and then never updates the index; `sync` beside one is safe, codegraph's own lock reports a busy index and nothing is forced); otherwise do nothing and say why.
- **SETUP-09** SHOULD — `doctor` tells how to install CodeGraph when its binary is missing (the installer commands and the docs link; spec11 never installs it) and judges the index's freshness from its last write against the newest source or test file, whether or not a codegraph process runs: older means a warning that names `sync`.
- **SETUP-10** SHOULD — `install` with `server=codegraph` adds the `codegraph` MCP entry (`{"type":"stdio","command":"codegraph","args":["serve","--mcp"],"alwaysLoad":true}`, what `codegraph install --print-config claude` prints) to `<repo>/.mcp.json`: the file is created if missing, other servers and keys are kept, an existing `codegraph` entry is never overwritten, and invalid JSON is left untouched (SETUP-02); `uninstall` with `server=codegraph` removes only that entry (customised or not, since the user asked), keeps the other servers, and deletes the file only when nothing else is left (SETUP-03), leaving the skill and the spec11 entry alone; `install_status` says whether the repo, and the global config (read-only), has it.
- **SETUP-11** SHOULD — the installed skill tells the agent to write or change the requirement before the tests and the code, and, when code or tests changed so that a requirement no longer matches, to show the user the requirement, what the code does now and the proposed wording, and to edit the requirement only after the user confirms: never silently, never by weakening a level to fit the code. (manual)
